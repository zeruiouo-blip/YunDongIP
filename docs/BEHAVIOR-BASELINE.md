# YunDongIP 行为基线冻结

以下项目在发布重写中不得擅自修改：

1. 扫描并发默认 200，上限 1000。
2. 每 IP 4 次 TCP 握手，扫描拨号超时 1 秒。
3. 扫描拒绝阈值为 loss >= 0.60。
4. 扫描结果批次大小 50；Trace 回填批次大小 50；Trace 并发 64。
5. 扫描阶段先把通过 TCP×4 的候选送入实时探测流；全球扫描时 Trace 在后台继续分类。
6. 前端消息协议必须保留 `scan_batch`、`scan_trace_batch`、`scan_progress`、`scan_complete_wait_dc`、`task_complete`。
7. 扫描中的探测流不能因为新结果到达而做全量排序或整表重绘。
8. 扫描过程中允许把已完成 CF Trace 的候选分批预整理到内存精测候选池，但不得做全榜排序或整表 DOM 重绘。
9. 正常完成与人工停止后，仍等待约 30 秒再完成最终排序；可视详细列表必须分批加载，避免一次性创建大量 DOM。
10. IPv4 采样模式固定为：full=120、compact=18、rotate2/3/4/5 为 120 样本分片。
11. 前端核心协议、字段与功能入口保持兼容；响应式布局与性能修复允许调整 HTML/CSS/JS 实现。
12. 动态 R2 → R4 流水线保持既定行为，不接受为“优化”而进行的机制改动。


## 启动方式

桌面用户直接运行官方 Release 二进制，不需要安装 Go。Windows/macOS/Linux 桌面环境默认监听本机 `127.0.0.1:13335` 并自动打开浏览器。服务器或无图形环境可使用 `-open-browser=false`；局域网访问可显式指定 `-host 0.0.0.0`。
