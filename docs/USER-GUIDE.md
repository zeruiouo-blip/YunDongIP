## 1. YunDongIP 是做什么的

YunDongIP 不是“扫描一次、选几个 IP、然后结束”的一次性测速工具。

它的完整思路是：

1. 扫描 Cloudflare Anycast IP。
2. 对每个候选做 TCP 握手粗筛。
3. 通过 Cloudflare Trace 识别 Colo / 地区。
4. 把合格候选整理到精测候选区。
5. R2 对候选做单 IP 5 秒下载测速。
6. 合格节点进入 R3 水库继续竞争。
7. R3.5 从当前较强候选中进行擂台复测。
8. 前 3 名可晋升到 R4 待命仓。
9. R4 持续巡检，不合格的节点会退回、冷却或淘汰。
10. 如果配置了 Cloudflare 域名，YunDongIP 可以把更合适的 IP 自动更新到域名 DNS。
11. 后续发现更好的 IP 时继续竞争并自动替换。

也就是说，用户最终只需要长期使用自己的固定域名，不需要自己反复手动找 IP、测速、复制、替换 DNS。

## 3. Windows 新手最快上手

### 第一步：下载

普通 Intel / AMD Windows 电脑下载：

YunDongIP-0.1.1-Windows-x64-Easy.zip

ARM Windows 设备才使用 ARM64 版本。

### 第二步：解压

不要直接在压缩包里面运行。

先解压到一个普通文件夹，例如：

~~~
D:\YunDongIP
~~~

### 第三步：双击运行

双击：

~~~
YunDongIP.exe
~~~

默认会：

- 在本机启动 YunDongIP 后端。
- 监听 127.0.0.1:13335。
- 自动打开浏览器控制台。

如果浏览器没有自动打开，可手动访问：

~~~
http://127.0.0.1:13335
~~~

### 第四步：看到“阵列连接成功”

右上角连接状态显示：

**阵列连接成功**

说明网页与本机 YunDongIP 核心已经建立 WebSocket 连接。

如果一直显示连接中或断开，先不要扫描，先检查程序是否仍在运行。

## 4. Android 使用方法

Android 0.1.1 是独立客户端，不需要电脑配合。

### 安装

下载：

YunDongIP-0.1.1-android-arm64.apk

安装后点击应用图标。

客户端会：

- 在手机本机启动 YunDongIP Go 后端。
- 使用本地 WebView 打开完整控制台。
- 以前台服务维持运行。
- 扫描、精测、R2 / R3 / R3.5 / R4、Cloudflare 域名更新等仍然是完整功能。

### Android 后台注意事项

部分手机厂商会主动清理后台应用。

如果发现：

- 锁屏后停止运行
- 切到后台一段时间后自动断开
- 自动优选不能持续

可以在手机系统里给 YunDongIP：

- 允许后台运行
- 电池设置改为“不限制”或类似选项
- 不要开启强制省电

不同品牌手机名称可能不同。

# 7. 页面顶部按钮说明

## ⚡ 启炉扫描

开始一轮 Cloudflare IP 扫描。

扫描时部分控制按钮会锁定，避免一边修改配置一边扫描造成状态冲突。

## ⭕ 终止扫描

人工停止当前扫描。

停止后不会立刻把整个精测榜一次性塞进浏览器。

0.1.1 会等待约 30 秒进行最终整理，再显示精测榜。

## 👑 开启皇位争夺

开启持续自动优选流水线。

注意：

**扫描** 和 **皇位争夺流水线** 是两个概念。

扫描负责发现候选。

皇位争夺负责让已经发现的候选继续经过 R2、R3、R3.5、R4，并在配置 Cloudflare 域名后自动更新 DNS。

扫描正在运行时，持续流水线会让开资源，不与扫描抢占。

## ⏸️ 暂停皇位争霸

已经开启时，同一个按钮会变成暂停。

暂停后不会继续自动进行后续争夺，但已经保存的数据不会因为单纯暂停而全部删除。

## ⚠️ 释放熔断黑名单

把当前黑名单里的 IP 人工释放。

适合你认为之前测试环境异常、误判较多，希望重新给这些 IP 机会时使用。

不要把它理解成“清空所有数据”。

## 🧹 一键全部清除

清空当前海选 / 水库等主要运行数据。

这是破坏性较大的操作。

不确定时不要乱点。

## 主题按钮

目前有：

- 纯净白
- 黑粉
- 甜心粉

只改变控制台显示风格，不改变测速和优选逻辑。

# 8. 顶部数据栏说明

## 实时探测进度

显示当前扫描：

~~~
已完成数量 / 总任务数量

## 待命皇位储备

显示 R4 当前储备数量。

IPv4 / IPv6 各自有独立 R4 待命仓。

每条赛道最多 100 个物理 Slot。

# 9. “IPv4/IPv6上位门槛重置”是什么

这个按钮只清空当前 R3.5 的动态上位基准。

它不会：

- 删除 R3 候选
- 删除 R4
- 删除当前域名 IP
- 清空整个程序

下一轮 R3.5 会重新建立门槛。

当前按钮一次同时重置 IPv4 和 IPv6。

适合：

- 网络环境突然变化
- 高峰期整体速度发生明显变化
- 当前门槛明显不适合现在的网络

不建议频繁乱点。

---

# 10. “⚡ 即刻登基”是什么

正常情况下 DNS 自动上位由后台流程执行。

点击“即刻登基”会主动触发一次当前 DNS 同步判断。

它不是：

“随便拿一个 IP 强制写到域名”。

仍然会依据当前流水线和赛道状态处理。

# 11. IPv4 / IPv6 皇位卡片

顶部有两个独立赛道：

- IPv4 主皇位赛道，对应 Cloudflare A 记录
- IPv6 主皇位赛道，对应 Cloudflare AAAA 记录

卡片会显示：

- 当前绑定域名
- 当前在位 IP
- 自动 / 手动模式
- 当前承载网络
- Cloudflare Colo
- 实测速度
- 防抖时间
- 在线 / 稳坐时间

## 2 分钟防抖

新 IP 登基后有约 2 分钟防抖期。

目的是避免刚换上一个 IP，下一秒又因为轻微速度波动马上换掉。

## 自动模式

允许 YunDongIP 根据持续优选结果自动更换 IP。

## 手动模式

用户指定 IP 后，可以让该域进入手动状态。

自动流水线不会按照普通自动域名的方式随意替换它。

## 画像

打开这个 IP 的数字身份证。

## 指定

人工输入一个 IP，让它绑定到对应子域。

## 删

删除这个子域赛道配置。

# 12. 全息数字身份证

数字身份证用来查看某个候选 / 皇位节点的详细信息。

当前会显示：

- 节点 IP
- 实测极速
- 握手延迟
- Cloudflare 落地机房
- 承载网络 / 本地公网出口运营商信息
- 建档时间
- 当前路径展示

### 本地地区怎么来的

0.1.1 已经取消固定“杭州”。

程序启动后会自动识别当前运行设备的公网出口地区和运营商。

后台还会定期刷新。

因此：

- 杭州用户可能显示杭州
- 北京用户可能显示北京
- 美国网络可能显示对应美国地区
- 使用 VPN / 代理出口时，显示的可能是公网出口所在地区

这里代表的是**当前公网出口识别结果**，不是 GPS 定位，也不是在读取用户家庭地址。

### 点击节点为什么会定格

手动点击某个节点查看画像后，会暂时锁定约 5 分钟。

否则在有多个域名时，数字身份证会自动轮播当前在位节点。

# 13. 数字身份证三个操作

## 授予免死

给当前节点增加保护标记。

适合你暂时不希望某个重要节点被普通处理逻辑轻易清理时使用。

再次操作可以取消。

## 打回第3轮

把节点从当前较高层级退回 R3 水库继续竞争。

## 物理处决

彻底删除该节点当前档案并拉入黑名单。

这是比较重的操作，不建议新手随便点击。

# 14. 探测参数矩阵

这是扫描前最重要的区域。

## IPv4 / IPv6

可以选择：

- 只扫 IPv4
- 只扫 IPv6
- 两者都扫

如果你的本地网络没有 IPv6，IPv6 测试结果可能受到本地网络能力限制。

## TCPing / HTTPing / TCP+HTTP

0.1.1 的**扫描第一阶段固定使用 TCP×4 + CF Trace**。

界面上的 HTTPing / TCP+HTTP 属于后置精测方向。

也就是说，不要把它们理解为会把当前第一阶段扫描改成另外一套扫描器。

当前主扫描流程仍是：

TCP×4 粗筛 → CF Trace → 精测候选。

# 16. 合格延迟

默认：

~~~
500 ms
~~~

这是扫描阶段用于限制候选延迟的参数之一。

数值越严格，留下的候选越少。

新手不建议一开始就设得特别低，否则可能出现：

“扫描了很多 IP，但几乎没有候选。”

# 17. 并发线程

默认：

~~~
200
~~~

当前界面允许最大：

~~~
1000
~~~

并发越高不代表最终结果一定越好。

过高并发可能造成：

- 本地路由器压力
- NAT 表压力
- 系统连接压力
- 网络瞬时拥堵
- 大量握手同时失败
- 反而增加误判

如果不知道怎么设置，先用默认 200。

每轮约 30 个 / 段。

每轮约 24 个 / 段。

# 20. 一次扫描到底发生了什么

每个扫描候选会固定做：

**4 次 TCP 握手**

得到：

- 最低延迟
- 平均延迟
- 最高延迟
- 丢包率

当前扫描拒绝线：

**丢包率 >= 60%**

达到或超过这个值，本轮不会进入合格候选。

通过 TCP 粗筛后，会继续做 CF Trace：

- Colo
- 国家 / 地区
- 城市等分类信息

Trace 完成后，候选进入后续精测候选体系。

---

# 21. 探测流

“探测流”是扫描阶段的实时窗口。

它主要让你看到：

- IP
- Colo
- Trace 是否完成
- 丢包率
- 最低 / 平均 / 最高延迟

为了避免浏览器越扫越卡：

- 完整数据仍保存在后台
- 页面只保留最近一部分实时卡片
- 扫描中不会因为每来一个 IP 就全榜重新排序

所以“页面没显示全部卡片”不代表数据丢了。

---

# 22. 精测榜

精测榜不是扫描开始就疯狂重绘。

0.1.1 为了解决大扫描结束时网页卡死，改成：

- 扫描阶段已经开始分批整理候选
- 每约 240 个候选做一块预排序
- 扫描结束 / 人工停止后等待约 30 秒
- 再分批合并排序
- 初次详细列表只显示约 120 条
- 需要时继续加载更多
- 后续精测结果也采用节流批量排序，不是每来一个结果就全榜重排

所以扫描刚结束时看到“后台预整理”，属于正常现象。

不要因为没有立刻显示最终榜单就反复刷新网页。

# 23. 精测榜里的地区规则

精测榜上方有：

**R2 地区接入规则**

可以选择：

当前全部完成分类的地区都可以参与。

系统自动按地区轮转。

## 手动选地区

只让你勾选的 Colo 进入 R2。

当前固定：

**每地区 2 个 / 轮**

# 24. R2 是什么

R2 是真正下载测速的入口层。

它不会再负责做 CF Trace。

进入 R2 之前，候选应该已经在扫描阶段完成地区识别。

### 正常阶段

当前代码一次最多从精测候选组织：

**50 个候选**

内部是：

**10 组 × 每组 5 个**

每个 IP：

**独享 5 秒下载测速**

### R3 缺水时

如果某条 R3 赛道低于 50 个候选，会进入补水模式。

目标会尽量补到 100。

仍然遵守地区轮转和当前筛选规则。

### R2 通过条件

当前基础速度门槛默认约：

**1 MB/s**

如果实测速度低于基础门槛，会淘汰并进入黑名单。

### R2 0 速保护

第一次测到 0：

不会立刻杀掉。

会保留历史战力并给一次机会。

连续第 2 次仍然 0：

才会进入黑名单。

### R4 非常空的时候

如果某条 R4 少于 5 个待命节点，R2 中符合要求的节点可能直接补入 R4。

否则正常进入 R3。

---

# 25. R3 是什么

R3 可以理解为：

**已经通过真实测速，但还没进入皇储待命仓的竞争水库。**

它会保存候选：

- 当前速度
- 历史优秀速度
- 挑战次数
- 最近测试时间

R3 不是简单“进去就永远留着”。

它会持续动态变化。

---

# 26. R3.5 擂台是什么

R3.5 是 R3 到 R4 之间的竞争层。

当前逻辑会优先从 R3 当前较强候选中组织最多 10 个参赛节点。

不是随机把最下面一堆 IP 抓出来浪费测速时间。

每个参赛 IP再次进行：

**5 秒真实下载测速**

然后按实测结果重新排序。

### 晋级

本轮前 3 名，并且达到基础速度要求：

进入 R4。

### 没进前三

挑战次数 +1，回 R3 继续等待。

### 连续 5 次没晋级

进入：

**冷宫 30 分钟**

冷宫到期后：

- 挑战负罪清零
- 自动回到 R3

### 连续 2 次 0 速

直接进入黑名单。

---

# 27. R3.5 动态门槛

R3.5 不是永远拿历史最高速度死卡所有新人。

当前会根据最近优秀节点建立动态 Benchmark。

实际接入门槛使用当前 Benchmark 的约：

**70%**

同时不能低于基础速度底线。

门槛每约 30 分钟会重新建立周期。

这也是顶部为什么有：

**IPv4/IPv6上位门槛重置**

---

# 28. R4 是什么

R4 是已经通过多轮竞争后的优质待命仓。

IPv4 和 IPv6 分开管理。

每条赛道：

**100 个物理 Slot**

R4 节点还会持续被巡检，不是进入 R4 后就永久免测。

### R4 巡检

每次拿当前物理 Slot 中的节点重新做 5 秒实测。

如果速度表现已经逊于 R3 当前前部优秀候选，它可能被退回 R3 重战。

### R4 0 速保护

第一次 0 速：

保留历史成绩，先给机会。

连续第二次 0：

从 R4 删除并加入黑名单。

---

# 29. 单根测速总线是什么意思

R2、R3.5、R4 的真实下载测速共享一条全局测速总线。

目的：

**任意时刻只让一个真实下载测速任务占主要测速带宽。**

否则如果十几个测速同时跑：

- 互相抢带宽
- 每个结果都被压低
- 排名会失真

所以看到有很多候选排队是正常的。

YunDongIP 更重视可比较的测速结果，而不是同时并发跑几十个下载测速。

---

# 30. 冷宫

“禁锢冷宫”主要放暂时失去竞争资格的节点。

当前典型情况：

R3.5 连续 5 次没能晋级前三。

冷宫时间：

**30 分钟**

到期后会自动回 R3。

页面也提供：

- 特赦：立即让它重新获得机会
- 处决：人工删除

---

# 31. 黑名单

黑名单比冷宫更严重。

例如：

- R2 连续 2 次 0 速
- R4 连续 2 次 0 速
- 一些长期失去竞争价值的候选

可能进入黑名单。

顶部“释放熔断黑名单”可以人工清空黑名单，让这些 IP 未来重新被发现。

---

# 32. 退役阁

一个 IP 曾经真正上过域名，后来被更好的节点替换，会进入退役记录。

退役节点仍然可以：

- 查看画像
- 手动重新上位
- 回到 R3
- 删除

退役阁按：

- 白天
- 晚高峰

分别记录。

---

# 33. 白天 / 晚高峰模式

当前默认时间：

- 白天：其它时段
- 晚高峰：19:00 ～ 24:00

到时段切换时，系统会处理对应 R4 储备的封存 / 解冻。

这样白天表现好的节点和晚高峰表现好的节点，不必永远混成一套固定排名。

页面的“昼夜封存与退役库”可以看到这些数据。

---

# 34. Cloudflare 域名自动更新怎么配置

这是自动“登基”的关键。

右侧有：

**皇权凭证与子域开辟**

需要填写 Cloudflare API Token。

### Token 需要什么能力

YunDongIP 当前代码需要：

1. 能列出你可用的 Zone。
2. 能读取 / 创建 / 修改 / 删除对应 Zone 的 DNS 记录。

因此创建 Token 时，请给目标域名所需的 Zone 读取和 DNS 编辑能力，并尽量只限制到你准备给 YunDongIP 使用的域名。

不要使用不必要的全账号高权限 Token。

### 填入 API Token

填入后程序会尝试自动拉取根域。

也可以点：

**🔍 拉取根域**

### 选择根域名

例如你 Cloudflare 里有：

~~~
example.com
~~~

选中它。

### 开辟争霸子域

填写前缀，例如：

~~~
cf
~~~

如果选择 IPv4：

最终对应：

~~~
cf.example.com
~~~

A 记录赛道。

如果选择 IPv6：

对应 AAAA 记录赛道。

可以建立多个子域赛道。

# 35. API Token 会保存在哪里

桌面 / CLI 版本会把当前流水线配置保存在运行目录下的：

~~~
pipeline_config.json
~~~

其中包含 Cloudflare Token 等配置。

这个文件属于运行数据，不应该提交到公共 GitHub。

所以：

- 不要把 pipeline_config.json 发给别人
- 不要把自己的 Token 截图公开
- 不要上传到 Issue
- 分享日志时注意有没有敏感信息

Android 使用应用自己的私有运行目录保存数据。

---

# 36. A / AAAA 冲突处理

当某个子域按 IPv4 A 记录登基时，YunDongIP 会尝试清理这个同名子域残留的冲突 AAAA 记录。

反过来：

AAAA 登基时会处理同名冲突 A 记录。

因此不要把同一个完全相同的子域名同时当成互相独立的 A / AAAA 业务配置，除非你明确理解当前程序的冲突清理行为。

更稳妥的方式是：

- IPv4 用一个子域，例如 cf4.example.com
- IPv6 用另一个子域，例如 cf6.example.com

---

# 37. 自动登基规则的大概逻辑

自动模式下：

1. 从 R4 找当前适合的候选。
2. 避免同一个 IP 同时被重复分配给多个自动子域。
3. 当前域名没有 IP 时，可以直接选合格节点上位。
4. 已经有在位 IP 时，会考虑 2 分钟防抖。
5. 白天更倾向于新候选速度超过当前在位速度后再替换。
6. 晚高峰使用自适应逻辑处理当前候选。
7. 成功更新 Cloudflare DNS 后，旧节点进入对应时段退役阁。

批量操作只是把候选加入队列。

真实下载测速仍然遵守全局单车道，不会同时十几个测速互相抢带宽。

# 40. 为什么有些按钮扫描时不能点

这是故意的。

扫描运行时修改：

- 域名
- R2 设置
- 皇位状态
- 黑名单
- 候选状态

容易造成扫描数据和流水线数据同时变化。

所以当前前端会在扫描时锁定部分操作。

需要修改这些内容时：

先停止扫描，再操作。

# 41. 推荐新手第一次怎么用

如果完全不知道参数怎么设置，先按下面来：

1. IPv4 勾选。
2. 本地有 IPv6 再勾 IPv6。
3. 端口保持 443。
4. 合格延迟保持 500 ms。
5. 并发保持 200。
6. 地区筛选留空。
7. 采样先使用默认全量，或者机器 / 网络压力大时选分片轮换。
8. 点击“启炉扫描”。
9. 观察探测流。
10. 扫描结束后等待约 30 秒。
11. 打开精测榜。
12. 确认 R2 有候选。
13. 填写 Cloudflare Token。
14. 选择根域。
15. 建立测试子域。
16. 开启皇位争夺。
17. 先观察日志和 R2 / R3 / R4 流动，不要一开始就频繁手动重置。

# 44. 常见问题

## 扫描完精测榜没有立刻出现

先等约 30 秒。

0.1.1 会做延迟整理，避免大量候选同时排序造成网页卡死。

## 合格候选很多，但 R2 很少

不是所有扫描候选都会立刻同时进入真实测速。

R2 会按地区和单车道节奏逐个处理。

## 手机切后台后不工作

检查系统后台 / 电池限制。

## 数字身份证地区和我人所在城市不一样

它显示的是**公网出口识别地区**。

如果使用：

- VPN
- 公司网络
- 运营商异地出口
- 代理

出口地区和人实际所在地可能不同。

## 为什么测速不是同时跑很多个

因为真实下载测速使用单车道，避免互相抢带宽导致结果失真。

## 为什么 R4 的 IP 又掉回 R3

R4 仍然会巡检。

它不是永久皇族。

如果当前实力已经明显低于 R3 的新候选，会回去重新竞争。

## 为什么 IP 进冷宫

通常是多次擂台没有晋级。

冷宫是冷却，不是永久删除。

## 为什么 IP 进黑名单

典型原因包括连续 0 速或低速淘汰。

如果怀疑当时网络异常，可以手动释放黑名单重新测试。
